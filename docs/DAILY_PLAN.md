## 什么算项目完成

这是交付计划，不是已完成记录。11/25 签收前必须有以下可打开的产物：

1. **来源和起点**：数据 manifest/ID/SHA、实际环境 health/fingerprint、SFT B1 基模 revision、adapter 权重与配置哈希。Jun 已在 #14 记录采用 #18 原 SFT 身份；Zqqq 的数据采用、设备端文件核验、Qiu 的登记验收分别完成。不能把 PPO checkpoint 当 SFT B1。
2. **真实 RL 闭环**：至少一条策略链完成三轮“当前策略新采样→更新→保存→下一轮新采样”，含独立进程继续训练、旧概率重放、critic/优化器恢复和参数变化证据。CPU 测试、同进程重载或反复读取旧 JSON 不替代此项。
3. **真实主对照**：从同一 SFT 起点分别训练两奖励臂，共同算法与协议、明确预算口径、统一评估。最低交一个完整训练种子的两臂，目标为两个预先指定种子；只有一个种子时明确无法估计训练种子方差，不能声称多种子稳定提升。
4. **结果与结论**：B0/B1、两奖励臂的原始轨迹、实际配置、来源、逐 run 统计、配对差/区间、失败案例和资源限制。旧 B0/B1 结果只有通过来源/配置/完整性验收才复用，否则统一重评。
5. **交接包**：可执行命令、checkpoint 清单/校验值、固定版本结果表、方法图、约 5 分钟讲稿、离线演示和个人贡献记录。

工程验收不要求成功率必须提升；负结果可交付，但未运行、来源不明、对照失配不能算完成。关键门槛未过时，Zqqq 当天记录未完成或缩减范围并核对课程要求；不偷偷顺延到 12 月，不以 SFT 或奖励导出冒充 RL。

- **辅助项**：当前工程 beta=0 表示两臂都不加 grounding；只有记录确认后才作为主实验设置。若采用非零辅助项，两臂共享公式和权重，不沿用未审定的 CLI 默认值。

- **范围**：保留一个主要对照，不再增加基模、无必要 SFT 重训或同时追多个新估计器。额外消融只在核心闭环和主对照完成后、预算允许时运行。
