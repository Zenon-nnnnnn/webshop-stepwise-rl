# Proposal 实验协议与对照表（2026-11-17 草案）

状态：供组内 review，尚未冻结，也不是已完成实验。与 [实验操作手册](EXPERIMENTS.md)、[每日计划](DAILY_PLAN.md) 配套；本文件具体化公平对照和验收，不代表新增奖励路径或 RL 入口已经实现。

## 研究问题与假设

主问题：相同 SFT 初始化、RL 算法和预定交互预算下，逐步进度奖励相较终局奖励，是否提高独立 WebShop 任务的满奖励成功率？

辅助问题：SFT 相比基础模型是否改善购物表现？仅用最终得分训练的可加进度模型，在独立验证任务上能否预测总分，逐步归因又有哪些错误？

逐步奖励可能改善学习，也可能因错误归因、尺度偏差或奖励投机而变差。总分预测准确不能证明步级归因正确；负结果也作为结果报告。此项目先使用低成本线性可加估计器，不将其写成论文神经 SPA 的完整复现。

## 奖励定义与必须先解决的问题

设最终环境购物得分为 R，各步进度预测为 p_t，共同辅助项为 a_t：

- R-TG：前面步骤任务奖励为 0，最后一步任务奖励为 R；再逐步加 a_t。
- R-PG：各步任务奖励为 alpha × p_t；再逐步加完全相同定义的 a_t。
- alpha 起始候选为 1，最终数值、折扣 gamma、GAE lambda 和辅助项均须在正式实验前登记冻结。

当前 common.combine_rewards 的 spa 模式为 alpha × p_t + beta × g_t，g_t 是合法动作 1/非法动作 0；terminal 模式只返回终局 R，没有共同辅助项。不可把现有两模式直接作为公平主实验。

已用真实函数做过构造输入检查：进度总和均为 0.8、全部动作合法、alpha=1、beta=0.5 时，3 步奖励总和为 2.3，增加两个零贡献合法动作后的 5 步总和为 3.3。此结果是未折扣奖励总和的反例，不是实际策略已经投机的证据，也不能直接推断采用折扣后的回报排序。

**推荐待审方案**：保留原始 grounding=0/1 日志作为评估字段；训练辅助项另定义为“合法动作 0，非法动作 -beta”，候选 beta=0.1。不要改写原始 grounding 为负数，否则现有指标会误读。该方案能消除单纯因多做合法操作获得的额外正分，但不保证消除所有投机，也不等同于论文原公式。Jun、Qiu review 后确定是否采用；本 PR 不修改奖励代码、不宣称方案已冻结。

无论采用什么方案，两臂一致；若决定 beta=0，也必须两臂同时为 0 并说明不含合法性辅助奖励。不要单独给逐步臂额外奖励。正的进度预测本身也可能奖励循环，须检查重复操作、分数尺度、轨迹长度与训练奖励的关系。

预测 p_t 的和目前只是近似 R，不保证守恒。正式运行前报告 val 上的总分 MSE、平均偏差与负分/异常值比例，决定是否需要尺度校准或约束。任何校准只用 train/val，在两臂预算登记之外单列其训练成本；不要把简单按比例归一化当作已实现功能，尤其须处理总和接近 0 或为负的情形。

## 固定条件与预算

| 必须保持一致 | 具体约束/证据 |
|---|---|
| 模型起点 | 两个 RL 臂加载同一 B1 adapter 和基础模型 revision；记录 SHA |
| 数据边界 | 同一 train/val/test 协议，按底层任务隔离；测试不进入 SFT、进度拟合或调参 |
| 环境 | 同一资产、goal-map fingerprint、任务分布和动作接口 |
| 输入与生成 | 同一 system prompt、chat template、上下文裁剪、最大动作数、解码配置 |
| 优化 | 同一 RL 算法、LoRA 配置、优化器、学习率、batch、KL/熵设置和更新规则 |
| 辅助奖励 | 相同公式、权重、落点、终止/截断处理 |
| 检查点选择 | 同一预定 val 指标与规则，例如主要按 val 成功率选择，平局按平均购物得分，再平局选较早 checkpoint；冻结后不看 test 选模型 |
| 随机性 | 至少两个配对 RL 种子为目标；固定同一 SFT 初始化，不声称测了 SFT 初始化方差 |

主预算按环境交互步数计，预先登记每臂总步数上限、采样批量、最大更新轮数和每轮优化上限。不同轨迹长度会使总步数、任务数、tokens、更新次数无法全部严格相等，因此以预定交互预算为主，报告其余实际消耗。末批允许的超额上限须事前固定并如实记录，不删除长/失败轨迹来凑预算；某臂提前技术中断时不能冒充匹配预算实验。

为比较学习效率，在相同预定交互步数节点做 val 评估；评估成本单列，不计入训练采样。P0 的采集/训练成本也单列，不能隐藏逐步臂额外成本。具体任务数量、tokens、优化参数与容量在 11/20 实测后填入运行配置，未填齐不能启动正式对照。

## 指标与统计口径

| 指标 | 定义与用途 |
|---|---|
| 主指标：满奖励成功率 | done=true 且最终环境奖励 ≥ 1-1e-6；购买结束不等于成功 |
| 平均最终购物奖励 | 所有预定有效评估 episode 的 final_reward，包括失败；不用训练奖励替代 |
| 平均交互步数 | 包含非法动作与步数耗尽；同时列终止原因，避免把提前失败误当高效 |
| 非法动作率 | 非法尝试次数 / 所有动作尝试次数；与任务是否买对分开 |
| 资源成本 | 实际环境步数、任务数、生成 tokens、更新次数、GPU 时间与显存 |
| 进度模型诊断 | 独立 val 总分 MSE/偏差、逐步案例、循环分数与长度关系；不是因果贡献真值 |

相同冻结任务评估所有方法，按 task 配对比较。每个种子单独报告；有重复轨迹时按 task 聚类分析，不把轨迹数当独立任务数。Qiu 提供配对/任务聚类区间及其假设；少量训练种子不能支持夸大的稳定性结论。单方法单任务一次评估时可列 Wilson 区间，但它不能替代方法差值的配对分析。

每次先核对 metadata.selected_ids 与完成记录一致。正常策略失败/超时保留；模型加载、环境服务等工程错误单列为未完成，按预定重跑规则补齐。补齐前只称部分结果，不能偷偷缩小分母。原始日志、配置、commit、split SHA、模型 SHA 与环境 fingerprint 进入实验登记。

## 可直接用于 proposal 的实验段落

我们以同一基础模型建立 B0 与 QLoRA SFT 基线 B1。在任务及底层购物指令隔离的训练集合采集轨迹，以最终购物得分监督低成本可加进度估计器，并在独立验证任务上检查总分预测误差与步级归因案例。主实验从同一 B1 检查点出发，比较终局任务奖励与逐步进度奖励，两臂固定相同的动作合法性辅助规则、RL 算法及预定环境交互预算。正式比较前将排查额外合法操作累积分的风险并冻结奖励协议。我们在相同独立任务上报告满奖励成功率、平均最终购物得分、交互步数、非法动作率及资源成本，采用任务配对分析并报告各训练种子结果。测试集合仅在配置与模型选择规则冻结后使用；逐步奖励的收益是待检验假设，不预设性能提升。
