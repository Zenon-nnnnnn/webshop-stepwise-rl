## 核心对照与验收口径

- B0：统一基础模型 + 购物提示词。
- B1：同一基础模型的 SFT。
- R-TG：B1 初始化，终局奖励 + 固定 grounding 权重的 RL。
- R-PG：同一 B1 初始化，可加进度奖励 + **相同** grounding 权重的 RL。
- 可选消融仅选一个：去 grounding，或减少进度训练数据；先完成可信主实验再做。

终局臂和逐步臂若同时改变 grounding，就不能把全部差异归因于进度分配。当前 CLI 的 `terminal` 模式未加 grounding，**计划中需要新增明确的 TG 奖励路径并验证**，不能误称现有导出已完成该控制。

两臂固定模型、初始化、prompt、上下文、动作上限、优化器/算法与可比的环境步数/更新预算，记录生成 tokens、GPU 时间和实际样本数。按任务划分 train/val/test，不按单条轨迹随机混分。进度估计先用现有线性基线验证接口；神经 SPA 为资源允许时的进一步复现，不把线性模型说成论文原模型。

主算法优先 PPO。若旧 PPO 兼容性持续阻塞，则在 11/24 的路线核对中准备一个明确标注的 on-policy REINFORCE/策略梯度学习分支；两种奖励臂使用同一算法。采用该分支意味着缩小 SPA-RL/PPO 精确复现范围，但保留真实 Agentic RL 实践。不能将 SFT 重命名成 RL，或把离线缓存响应直接当成当前策略样本。

## 真 RL 的证据清单

1. 每轮轨迹记录采样策略 checkpoint/hash、采样参数、task ID 与环境 fingerprint。
2. 用于动作概率的 token 与训练 mask 对齐；观测、padding 等 token 不作为 agent 动作学习。
3. PPO 需要可核对的行为/旧策略概率、value/GAE、ratio/clipping 与 KL；训练/推理 dropout、temperature、top-p 导致的分布差异必须解释。若采用简单 on-policy 起点，可先用 temperature=1、top-p=1，避免未建模的采样分布变换。
4. 更新前参数与更新后 adapter 真实不同，有效梯度/loss 有限，未意外更新冻结权重；零优势批次不伪装成学习成功。
5. 保存后重载可复现对应策略输出/概率，并能采新轨迹；不能把多次读取同一旧 JSON 当作多轮交互。
6. 小批更新只证明训练闭环；独立任务上的对照与不确定性才用于性能结论。

## 规模、种子与异常

正式任务量在 11/20 实测后冻结，12/07 前完成配置选择。优先完成两奖励臂、同预算、至少两个 RL 采样/训练种子；如果计算预算无法做到，应事先说明并降低结论强度，不能隐藏失败种子。共享 SFT 初始化与不同 RL 随机种子要区分，不能声称已测了 SFT 初始化方差。

有重复任务轨迹时不能把所有轨迹当独立任务扩大置信度。使用配对任务比较或按 task 聚类的 bootstrap，并报告种子层结果；统计实现由 Qiu 核对。预设开发/测试任务间的相似性限制应在报告中说明。

全部奖励为零时，先核查格式、模型加载、任务映射、步数/上下文和成功判定，再在训练集合内设计适当探索。调试子集变化需记录；不能删除困难测试任务制造提升。环境/网络异常单独记录，不混成策略失败。
