# 研究问题、项目范围与贡献边界

## 动机

多步骤 agent 通常在任务末尾才收到奖励。失败时，最终的 0 分难以区分哪一步有帮助。SPA-RL 研究将最终表现分解成每步进展，再结合动作可执行信号来训练策略。本组关注它在单卡、少量轨迹、小模型条件下的适用性。

## 研究问题

1. 在独立购物任务上，SFT 相比相同基础模型和提示词是否改善表现？
2. 轨迹总分监督能否学出具有一定预测能力的逐步分数？预测误差受数据量与成功/失败分布怎样影响？
3. 在训练预算相近时，逐步奖励与仅最终奖励相比是否改善任务完成情况？第三项需要实际策略更新实验，不能仅凭奖励预测误差回答。

假设是待验证的，不是结论。负结果也需要保存配置与失败案例。

## 交付范围

必须：WebShop 环境、来源声明、独立划分、基础模型 vs SFT、统一评估、运行证据、失败案例。

研究主线：独立进度模型训练/验证、逐步奖励构造、同一模型与训练预算下的 terminal vs stepwise RL 对照。

扩展：探索轨迹规模的消融。不要同时扩展三套环境、多个大型模型、大量奖励权重和复杂 UI。

如果 RL 到 12 月初仍未通过实机检查，应在报告中明确改为“参数高效微调与进度预测分析”，并对照课程 rubric 确认是否满足要求，不能继续使用暗示完成完整 RL 的结论。

## 模型选择

默认配置为 `Qwen/Qwen2.5-1.5B-Instruct`，便于在资源预算内先建立流程。可选 `meta-llama/Llama-3.2-3B-Instruct` 接近原论文模型，但需要 Hugging Face 模型访问许可并实测显存。比较方法时必须保持基础模型一致。

不能把不同模型、不同上下文长度或不同量化方式造成的差异都归因于奖励。

## 与原论文的关系

复用：购物环境、检索资产、参考轨迹格式、SPA 研究思路和原始训练代码。

新增：任务/指令分组划分、上游数据审计、单卡 SFT 工具、环境与 GPU 进程隔离、严格动作解析、成功率统计、可加线性进度基线、团队实验记录和文档。

## 基本术语

| 名称 | 含义 |
|---|---|
| episode / trajectory | 一个购物任务从开始到购买或步数上限的全部交互 |
| SFT | 对已有购物对话做监督训练；本工具仅在 assistant 回复上算 loss |
| grounding | 动作格式正确且在当前可执行列表中 |
| final reward | WebShop 环境返回的任务完成程度，通常在购买后产生 |
| success | 本项目定义为 `done` 且最终奖励近似 1 |
| progress estimator | 输出逐步分数，其总和拟合最终奖励 |
| PPO | 需要策略采样、旧策略概率、优势估计及约束更新的 RL 方法 |
