# 11/21 How 执行交接补充

按 [Zqqq 的交接](https://github.com/Zqqq-qq/webshop-stepwise-rl/issues/4#issuecomment-7061028273)补齐同批 B1 基线。原 B1 在 192、432、1865、2247、2584、9254、9693、10216 上以 FP32、贪心解码、max_steps=10 运行，和既有两组三轮 checkpoint 使用同一服务与设置。

B1 购买 7/8、满分 5/8、平均终局奖励 0.6708、无效动作 8/37。两组 RL 都购买 8/8、满分 5/8、平均终局奖励 0.7125、无效动作 1/29。八任务用于工程定位，不能据此声称总体提升。原始轨迹的本机路径和哈希见 baseline.json。

六次更新证据已共享到私有 Release 并在 Issue #4 回传。Jun/Qiu 的独立验收尚待完成。拟议执行单位于 proposed-execution.json，状态为待负责人确认。

建议最小可行路线为终局奖励与规则规格势函数的小规模主对照，原因是两者已有可执行、循环守恒的更新路径。若采用，研究问题和 proposal 应改成规则塑形对终局奖励的比较。学习型估计器保留失败诊断与局限，避免声称神经 SPA 复现。此项为建议，正式路线由 Zqqq/Qiu 决定。

建议先完整执行 seed42 的两臂，再按事前确认的预算执行 seed43。每臂 4 更新、每更新 4 个任务，共同 max_steps=8/max_new_tokens=128 上限。实际决策和 token 可能因提前结束不同，必须逐 run 报告。预计每种子双臂 1–4 小时，两种子 2–8 小时是资源预留，来自小规模时间跨度与 token 上限的粗略外推；模型加载、长样本与失败重试有不确定性。当前验证8任务每模型约 1.6–2.1分钟，扩到160任务须实测长尾，不作为准确工期。

遇到概率重放、身份、非有限数或环境中断即停止受影响作业、保留原件。不根据验证结果追加更新。最终测试仅在负责人完成门禁后执行。
